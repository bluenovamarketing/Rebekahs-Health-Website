## Scene 1 — Clear the website cache safely

This lesson shows you how to clear website cache safely after an approved content change. Cache clearing does not save your work and does not correct wrong information. We will save first, clear only the cache that applies, refresh the browser, and verify the exact public page on desktop and phone.

## Scene 2 — Required WordPress access

An Editor may use an available record or page Clear Cache action. Sitewide Breeze or Varnish controls may require an Administrator or Blue Nova. Never give someone Administrator access only to clear cache. Use only the control your role and instructions allow.

## Scene 3 — Clear cache only when a saved change is stale

Clear cache when WordPress confirms a correct saved change but the public page still shows older information. Do not clear cache before saving, and do not use cache clearing to fix incorrect text, images, dates, or links. First correct the content and save it once.

## Scene 4 — Save the correct item once before clearing cache

Finish and review the approved change. Select Save, Update, or Publish one time and wait for confirmation. Copy or keep the exact public address that visitors use. You will use that same address for every verification step, without adding question marks or test text.

## Scene 5 — Start with the smallest applicable cache

Return to the list containing the item you changed. Find the exact row and use its Clear Cache action when that action is available. This is the smallest and safest first step. Do not clear unrelated pages, products, events, or practitioner records.

## Scene 6 — Refresh the browser without changing the URL

Open the exact public address. On Windows, press Control plus F five for one hard refresh. On a Mac, press Command, Shift, and R. Read the visible page and confirm whether the saved information now appears. Do not keep refreshing repeatedly.

## Scene 7 — Check in a private window when the browser stays stale

If the regular browser still looks old, open a private or Incognito window and paste the same exact public address. If the private window shows the correct result, the website is updated and the remaining issue is the regular browser's local cache. Do not add cache-busting text to the address.

## Scene 8 — Use Breeze only when a broader purge is approved

Use the approved Breeze Purge All Cache control only when a saved change affects a shared page or several pages and the smaller cache clear was not enough. Select the purge one time and wait. Do not change Breeze settings, preload options, minification, or optimization controls.

## Scene 9 — Leave Cloudways and Varnish controls to authorized users

A Varnish purge may be needed when correct saved content remains stale after the applicable page and Breeze cache are cleared. Use only an approved purge control when you were specifically authorized. Do not open server settings, restart services, disable Varnish, or experiment. Ask Blue Nova when the control is missing.

## Scene 10 — Never solve cache trouble with random settings

Do not repeatedly select Update or Publish. Do not purge object cache, Redis, a C D N, the database, image cache, or unrelated plugin caches unless Blue Nova directs you. Do not install, disable, or configure optimization plugins. Random purges can create a larger problem without fixing the original page.

## Scene 11 — Verify the visible public result on desktop

Open the exact public page with no extra address text. At desktop size, read the changed text, image, date, link, or listing. Click every public link affected by the change. Confirm that the page still fits the screen and nothing runs off the side.

## Scene 12 — Repeat the check on a phone and know when to stop

Repeat the same check at phone size. Confirm the changed information, images, buttons, and links remain readable and usable. If the saved result is still wrong or missing after the approved cache steps, stop and contact Blue Nova instead of purging again or changing server settings.

## Scene 13 — Always finish with the same three checks

Every content change ends the same way. First, save the correct content once. Second, clear only the applicable cache. Third, open the exact public address and verify the visible result on desktop and phone. If it is still wrong or missing, stop and contact Blue Nova.
